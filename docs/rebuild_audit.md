# Rebuild Audit

Date: 2026-05-05

## Baseline Commands

Run from the cloned repository before the rebuild:

```bash
python -m pip install -r requirements-dev.txt || true
python -m pytest -q
python cardboxgen_v0_1.py --preset tray_open_front --inner-width 135 --inner-depth 90 --inner-height 225 --thickness 3 --kerf 0.2 --clearance 0.15 --out out.svg
python examples/generate_examples.py
python tools/sync_docs.py
```

Observed baseline:

- `pip install -r requirements-dev.txt` succeeded; `pytest` was already installed and `pyclipper` installed successfully.
- Existing test suite passed: `5 passed in 0.03s`.
- The legacy CLI generated `out.svg`.
- `examples/generate_examples.py` completed.
- `tools/sync_docs.py` copied both root Python files into `docs/`.

## Risks Found

- The repository had two generator implementations: `cardboxgen_v0_1.py` and `cardboxgen_v0_7_templates.py`.
- The web app loaded `docs/cardboxgen_v0_7_templates.py`, while tests and examples loaded `cardboxgen_v0_1.py`.
- `/docs` contained hand-maintained/copy-synced Python duplicates.
- Version strings disagreed across README, Python, docs app, and i18n files.
- The v0.7 template prototype used independent phase-based finger generation, while the older generator used shared mating plans.
- Traditional and Simplified Chinese i18n files were missing hundreds of keys compared with English.
- CI deployed Pages but did not enforce tests or docs bundle freshness.

## Fixes Applied

- Created the `cardboxgen/` package as the only generator source of truth.
- Replaced legacy root Python scripts with thin compatibility wrappers.
- Added `docs/cardboxgen_bundle.py`, generated by `tools/sync_docs.py` from package modules.
- Updated the web app to import `cardboxgen_bundle.py`.
- Added structured API output: `svg`, `warnings`, `meta`, and `bundle_files`.
- Added first-class preset support and legacy alias warnings.
- Added explicit kerf/clearance depth and width compensation in `joints.py`.
- Added SVG layers `CUT`, `SCORE`, and `ENGRAVE`.
- Normalized i18n keys and versions across `en`, `zh-Hant`, and `zh-Hans`.
- Added tests for API, CLI, SVG validity, layout, edge-pair metadata, docs sync, i18n consistency, examples, and version alignment.
- Reworked CI so tests and docs sync checks run before release/deploy work.

## Remaining Mechanical Assumptions

- The layered rotary candy machine is a plausible prototype for dry flowing solids, not a certified dispensing mechanism.
- Divider rack slots/tabs are practical starting geometry and should be test-cut in the target material.
- Kerf compensation assumes a simple average kerf model; real laser behavior depends on material, focus, speed, power, and air assist.
