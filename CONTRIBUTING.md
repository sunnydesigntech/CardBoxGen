# Contributing to CardBoxGen

CardBoxGen is a geometry-first project. A change is not complete just because the SVG parses or the UI looks better; generated parts must satisfy the fabrication and assembly invariants for the supported parameter domain.

## Development Setup

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

For web work, regenerate the Pyodide bundle before testing the static app:

```bash
python tools/sync_docs.py
python -m http.server 8000
```

Open:

```text
http://localhost:8000/docs/
```

## Required Checks

Run these before opening a pull request:

```bash
python -m pytest -q
python -m pytest -m slow -q
python examples/generate_examples.py
python tools/sync_docs.py --check
```

For geometry or preset changes, also run CLI smoke generation for all first-class presets:

```bash
python -m cardboxgen --preset tray_open_front --inner-width 135 --inner-depth 90 --inner-height 80 --thickness 3 --kerf 0.2 --clearance 0.15 --out /tmp/tray.svg
python -m cardboxgen --preset dispenser_slot_front --inner-width 135 --inner-depth 90 --inner-height 80 --thickness 3 --kerf 0.2 --clearance 0.15 --out /tmp/dispenser.svg
python -m cardboxgen --preset window_front --inner-width 135 --inner-depth 90 --inner-height 80 --thickness 3 --kerf 0.2 --clearance 0.15 --out /tmp/window.svg
python -m cardboxgen --preset box_with_lid --inner-width 135 --inner-depth 90 --inner-height 80 --thickness 3 --kerf 0.2 --clearance 0.4 --out /tmp/box_with_lid.svg
python -m cardboxgen --preset divider_rack --inner-width 135 --inner-depth 90 --inner-height 80 --thickness 3 --kerf 0.2 --clearance 0.15 --out /tmp/divider.svg
python -m cardboxgen --preset card_shoe --card-width 63 --card-height 88 --card-thickness 0.35 --capacity 60 --thickness 3 --kerf 0.2 --clearance 0.15 --out /tmp/card_shoe.svg
python -m cardboxgen --preset candy_machine_rotary_layered --max-piece 18 --thickness 3 --kerf 0.2 --clearance 0.2 --out /tmp/candy.svg
python -m cardboxgen --calibration --thickness 3 --kerf 0.2 --out /tmp/calibration.svg
```

## Geometry Rules

- Inner dimensions are authoritative for box/tray presets.
- Every mating edge pair must share one `FingerPlan`.
- Finger masks must be complementary.
- Edge profiles must start at `(0, 0)` and end at `(length, 0)`.
- Fingered edges must reserve clean corner zones.
- Builders must not silently clamp impossible geometry.
- Blocking validation errors must prevent exportable SVG output.

## Web Rules

- `docs/app.js` must load `docs/cardboxgen_bundle.py`.
- `docs/cardboxgen_bundle.py` is generated by `tools/sync_docs.py`; do not hand edit it.
- Add new UI text to all files in `docs/i18n/`.
- Unknown or invalid browser input must show validation feedback, not crash generation.

## Documentation Rules

Update documentation when behavior changes:

- `README.md` for user-facing architecture, CLI, presets, and release notes.
- `docs/README.md` for GitHub Pages operations.
- `docs/fabrication_model.md` for fit/kerf formulas.
- `docs/wiki/*.md` for wiki-ready user documentation.
- `CHANGELOG.md` for release-facing changes.

## Pull Request Checklist

- Explain the geometry or user problem being solved.
- Include tests for new geometry rules or validation paths.
- Regenerate examples when output changes intentionally.
- Keep compatibility wrappers working unless a breaking change is explicitly planned.
- Note any remaining mechanical assumptions or prototype-only behavior.
